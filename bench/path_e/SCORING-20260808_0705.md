## The shared failure

`test_unparseable_value_raises` — failed by **both** non-thinking models, passed by both
thinking models.

c08 and c09 both constrained their value match to the literal alternation
`(Active|Not Active|N/A)`. An unparseable value therefore fails to match and is skipped
silently. c08's `raise ValueError(f"Unexpected value: {value}")` is unreachable dead code: the
regex that produced `value` cannot yield anything outside the alternation. c09 has no raise on
that path at all — its only non-match branch is `elif line.strip() == '': break`.

This is the failure mode the gold file names explicitly under "Claims a strong answer should
NOT make": *silently returning (False, False) for malformed input instead of raising
ValueError. Swallowing a bad flag makes a throttled run look clean, which is the exact failure
this harness exists to prevent.* Both coder specialists shipped exactly that.

c10 and c11 both split on `:` first and validate the value afterwards, so an unknown value
reaches a `raise`. That ordering is why they pass.

## Judgment detail

**c10 — 15/15 commentary.** Names the truncate-then-validate ordering with a correct mechanism,
then names block termination and *criticises its own implementation*: "relying solely on
`curr_indent <= block_indent` can prematurely exit if a subsequent section shares the same
indentation level." Block termination at dedent is one of the two answers the rubric awards 15
for. Quality 9: `val_map` lookup, error messages carry the offending key.

**c11 — 10/15 commentary.** Names genuine edge cases, but two of its three mechanisms are
wrong. It claims padding before truncation "silently breaks" `"123"` → `"1230"` → `"12"`; in
fact `"123".ljust(2,'0')` is a no-op and the result is identical either way. It then claims
`"101"` "would raise on the third character" under validate-before-truncate; `'1','0','1'` are
all valid and nothing would raise. Its block-scoping point is correct and earns the band.
Quality 7: `f"Invalid characters in flag field"` is an f-string with no interpolation and no
offending value; `'_'.join(label.lower().split())` duplicated; `break` on the first
colon-less line is a weaker boundary rule than c10's indent comparison.

**c09 — 10/15 commentary.** Names nested-reason flattening, a real requirement, with correct
reasoning. Marked down because it then asserts its approach is correct *because* it ignores
indentation — the rubric states that parsing every `label : value` line is not equivalent to
block-scoped parsing. It passed the dedent tests on this fixture, so the claim is not falsified
here, but it is the wrong principle. Quality 8: cleanest naming of the four
(`power_capped`, `thermally_throttled`).

**c08 — 0/15 commentary.** Emitted no closing commentary at all; the brief requires a ≤150-word
answer. 466 tokens, code only. Quality 5: unreachable `raise`; an `if len(field) != 2` check
after `ljust(2,'0')` that can never fire; and an exit-block heuristic
(`re.match(r'^\s*\S.*$', line)`) that is hard to reason about.

Contract 15/15 for all four: correct names, signatures, type hints, stdlib-only, single
runnable block, no placeholders.

## Verdict — coder slot

**c10 `qwen3.6:35b-a3b-mtp` wins the coder slot**, 99 vs 78 for the nearest coder specialist.
The 21-point gap is far outside the 3-point tie band, so speed does not break it.

This inverts the naive expectation. Both models *marketed* for code — `qwen3-coder:30b` and
Devstral — placed last, and they lost on the same defect: silently swallowing malformed input.
Round 1's `debug` task ranked c02 (27b) first and the coder specialists last at 38 points, and
`code` independently reproduces that ordering. Two different tasks, same conclusion.

**Latency is a genuine counter-consideration, recorded not suppressed.** c10 took 83.6s and
9,876 tokens where c08 took 2.24s and 466. For interactive editing that is a 37x wall-clock
penalty. The pre-registered rule is quality-first with a 3-point band, and 21 points is not a
tie, so the rule decides c10. If OH-GUI later needs a fast-path for trivial edits, c08 is the
candidate — but it must not be the default, because its failure mode is silent.
