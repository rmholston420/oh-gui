## The finding that matters most in this run

**Rep 3 finally articulated the mechanism c13 had missed in all nine previous draws** — and chose
Option B anyway.

Its second counter-argument reads: *"Compute Serialization & Latency. The GPU executes inference
sequentially. A classification request competes with the active model for GPU time… potentially
blocking the operator from timely safety interventions."*

That is the substance of `OLLAMA_NUM_PARALLEL=1`, which is precisely why `bench/gold/arch.md`
prohibits the "0 additional cost" framing of Option B. c13 reached the insight unaided, wrote it
down clearly, filed it under "arguments against my choice" — and left it there. Two paragraphs
earlier the same answer asserts *"Option B incurs 0 MiB additional VRAM cost."*

**So the failure is not missing knowledge. It is failure to let the knowledge move the decision.**
That is a materially worse defect in a planner than ignorance would be, because the reasoning
looks complete to a reader who is skimming, and the fatal objection is sitting in the document
labelled as survivable.

Rep 3 also has the best Option A rejection in the entire matrix, and it is worth preserving: a
co-resident classifier does not "cause OOM" — it *constrains the model menu*, forcing the operator
off the 35b and onto `qwen3-coder:30b`. That is the honest cost, correctly identified, where nine
other draws reached for "mathematically impossible."

## Rep 1: right answer, worst arithmetic of the run

Rep 1 chose Option C and identified both gold counter-arguments and the correct weakened property.
Its VRAM section then produces a **false conclusion** — *"Physical safety margin: −5,057 MiB
(negative headroom at max context)"* — which, taken at face value, says the system cannot run at
all. Four compounding errors:

1. It subtracts a KV-cache figure from a model footprint that **already includes KV cache**. The
   25,194 MiB measurement for `qwen3-coder:30b` is a total. Double-counted.
2. It applies **74.6 KB/token — the `27b` figure** — to `qwen3-coder:30b`, whose measured rate is
   110.0 KB/token.
3. It applies a **131,072-token** context to a model measured at **65,536**.
4. Its overhead midpoint is wrong: midpoints of 650–850 and 2,048–3,072 are 750 and 2,560, summing
   to 3,310, not the 2,700 used. It then abandons that budget entirely two paragraphs later when
   evaluating Option A (`32,607 − 26,994 = 5,613`, with desktop overhead silently dropped).

The decision survives because Option C needs no VRAM at all, so the arithmetic is load-bearing
only for the rejections. But criterion 2 asks for justification *against the measured numbers*,
and this mixes three models' figures to reach an impossible total. 16/30.

Its interface is the run's best: `ActionDisposition` separating dispositions from risk levels,
`matched_rules` for audit replay, two entry points (`analyze_action` and `analyze_text`), and a
caller contract that ties the trust dial to `taint_score` numerically. Not frozen, and
`action_type: str` is untyped — hence 17, not higher.

## Rep 2: misidentifies the weakened property

Criterion 4 asks which security property is weakened. Rep 2 answers *"semantic threat detection
accuracy."* That is backwards — Option B **is** the semantic option; sharing the model weakens
**independence**, not semantic capability. Rep 3 gets this exactly right (*"independence of the
security decision from the agent's reasoning state"*), as does rep 1. 9/15.

Rep 2 also never analyses Option C — section 2 covers A and B only — and claims classification
*"reuse[s] active model memory and KV cache,"* which is wrong: a fresh classification conversation
discards the KV cache. Its Option A estimate of 3,000–4,000 MiB for a 2B Q4 classifier is roughly
double.

## Self-contradiction worth naming, in rep 3

Compensation #1 requires *"zero user context, relying only on the action and ingested text as
inputs, preventing context bleed."* Its own interface then passes `context_window: str` into
`analyze()`. The port hands the analyzer exactly what the compensation exists to withhold. 12/25.
