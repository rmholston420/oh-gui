# Path E — run `20260808_0824` — THIRD planner-preset replicate, NOT the pre-registered test

## Read this before using these numbers

The command issued was `REPS=3 SAMPLING=precise bash bench/path_e/run_path_e.sh
c13_planner_arch_35bmtp`. **`SAMPLING` was not a variable the harness read.** The dump header
records what actually ran:

    sampling={'temperature': 1.0, 'top_p': 0.95, 'top_k': 20, ...}

Temperature 1.0 is the `planner` preset. `precise` is 0.6. Sampling came from the cell's
hardcoded role in `CELLS`, as `bench_path_e.py` line 222 did `SAMPLING[role]` with no override
path. The shell accepted the unknown variable and said nothing.

**Therefore the ADR-005 pre-registered `precise` test has NOT been run.** These three cells are a
third independent replicate set at the *planner* preset. Filed as such. The override is now
implemented and tested (`bench/tests/test_sampling_override.sh`), and an unknown `SAMPLING`
value is now a fatal error rather than a silent no-op.

## The pattern is now unambiguous and it is not a quality pattern

Sort all nine c13 answers by score and the decision sorts with them:

- Every answer scoring **79** chose **Option C** (`0738` rep 3, `0824` rep 3). Both are the
  best individual answers c13 has produced.
- Every answer scoring **54–66** chose **Option B**.

`0824` rep 3 is the strongest interface of any of the fifteen replicates across both cells:
frozen dataclasses throughout, an `ActionType` enum that includes `TEXT_INGEST` (so untrusted
text is covered without a second method), `TaintTag` carrying `propagation_rules`, and a
docstring that states the caller's obligation with `MUST`. Its falsifier is the best written in
the whole matrix — a numeric detection threshold **plus** an explicit statement of the evidence
required to establish it.

So c13's ceiling is higher than c12's. Its problem is that it reaches that ceiling roughly one
draw in five, and the other four draws it picks an option the gold analysis rules out. **This is
variance in the decision, not a deficit in capability** — the same conclusion ADR-005 reached
from three draws, now supported by nine.

## Errors, both directions

**Rep 1** notices its own contradiction and walks past it. Its table computes headroom for the
largest model as `28,685 − 29,698 = −1,013 MiB`, then annotates it *"Implies listed
sizes/overheads are optimistic or inclusive; the system is structurally saturated."* The
measured 29,698 MiB figure **already includes** everything; the negative number means the
premise stack is wrong, and the right move was to recompute, not to label the system saturated
and continue. Arithmetic elsewhere is correct (`3,491 − 2,048 = 1,443`).

**Rep 2** takes "midpoint of 650–850 + 2–3 GB" and gets `~2,850 MiB`. The midpoints are 750 and
2,500, summing to 3,250. It then rejects Option A for requiring *"`ollama stop` + reload × 2"* —
but Option A is a permanently resident classifier; it never swaps. Straw man.

**Rep 3**, which chose correctly, states `0.85 GB + 3.0 GB = 3,942 MiB` (it is 3,850) and calls
a dedicated classifier *"mathematically impossible… guaranteed OOM crashes"* — overstated, since
its own table leaves 2,525 MiB with the 27b resident, which fits a sub-1 GB classifier.

**All three reps assert Option B or C costs "0 MiB".** For C that is true. For B it is the claim
`bench/gold/arch.md` prohibits. **Across all nine draws, c13 has never once mentioned
`OLLAMA_NUM_PARALLEL`** — the setting that makes Option B serialise classification behind the
agent's own generation. That single omission is why it keeps reaching for B.
